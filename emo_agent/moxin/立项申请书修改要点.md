# 墨韵心调 2.0 · 立项申请书修改要点（汇总版）

本文档汇总对《大学生创新创业训练计划项目申请书》的**修改方向**与**可直接落地的写法建议**，与国家评审常关注点（创新性、落地性、科学性、团队匹配、社会价值、方案完整性）对齐，并与当前 **`D:\moxin` 实现能力** 保持一致，避免「文书与答辩演示不一致」。

---

## 一、总体原则

1. **名实一致**：申请书中的模型名称、调用方式、系统形态须与可演示原型、代码仓库、日志截图一致；不宜仅写「通义万相 / 豆包音乐大模型」若实际主线为 **EmoLLM + Stable Diffusion WebUI + 火山 BGM API**。
2. **创新点少而硬**：单独设「**项目创新点**」小节，**3～4 条**即可；每条尽量包含「**与已有工作差异** + **你们具体做什么**」，避免百科式技术堆砌。
3. **承诺可检验**：中期 / 末期指标写**保底可完成项**；大样本 RCT、多项生理指标、固定百分比疗效等医学化承诺易遭追问，宜降级为「拓展计划」或改为**用户体验 / 自评量表趋势**等合规表述。
4. **阶段化诚实**：多模态（微表情、生理信号）、群体共感、模型再训练等若尚未完成，应写清 **Phase 1（已具备）** 与 **Phase 2（计划）**，国评接受「路线图清晰的分期」。

---

## 二、技术表述与实现对齐（强烈建议统一口径）

| 申请书常见写法 | 建议调整为（与 moxin 一致时） |
|----------------|------------------------------|
| 视觉模型仅写「通义万相」 | **本地化 Stable Diffusion WebUI（`txt2img` API）** 作为主实现；可补充「接口层可兼容阿里云通义万相等」若确有计划 |
| 音频仅写「豆包音乐大模型」 | **火山引擎 BGM 生成（GenBGMForTime 等）**；豆包若用于对话/TTS 可单独写「对话与语音合成模块」 |
| EmoLLM 大段通用介绍 | 补一句**实际用法**：如文本输入 → JSON 情绪标签 / 强度 → 与 `emotion_to_prompt.csv` 联动 → 驱动文生图与音乐 prompt |
| 「视听文高度协同」仅口号 | 对应**工程事实**：payload 归档、模板选择、共情文案、图像与音频导出、日志（如 `smoke_test_log.csv`） |

**可选段落模板（可直接改写进「技术路线」）：**

> 情绪理解端采用本地 **EmoLLM** 推理，输出结构化情绪结果；模板层以 **`emotion_to_prompt.csv`** 建立情绪标签与国画风 prompt 的可解释映射；视觉生成调用 **Stable Diffusion WebUI** 标准 API；配乐调用 **火山引擎** 音乐生成接口并完成异步查询与落盘；前端采用 **Streamlit** 集成展示与流水线调度。后续可在统一接口下替换或增加其他多模态后端。

## 三、按章节：必改与增补清单

### （一）项目简介 / 立项依据

- **保留**：健康中国 2030、情绪健康问题、文化适配与非药物干预叙事。
- **收紧**：避免暗示「已具备临床疗效」，改为「**探索性干预体验与可用性验证**」。
- **新增一句**：与哈工大 Moods、Ellie、Magenta 等的**差异**（东方审美坐标 + 国画载体 + 视听文工程闭环）。

### （二）建议新增：「**项目创新点**」（独立小节，3～4 条）

以下为**表述框架**（需按最终技术选型微调措辞）：

1. **理论与维度创新**：在东方美学语汇下构建可操作的「情绪—国画意象」坐标（如豪放-婉约等维度与标注方案），突出相对西方情绪量表维度的**文化适配**。
2. **可解释映射创新**：国画要素（色彩、构图、意象关键词等）与情绪模板、prompt 字段的**规则化 / 表格化**联动，支撑复现与迭代（对应 CSV / 元数据设计）。
3. **多模态协同工程创新**：同一情绪诊断结果驱动 **文本疏导 + 国画生成 + 背景音乐** 的同步生成与 **payload** 级溯源，缓解多模态内容「各说各话」。
4. **应用场景创新（规划项如实写）**：在 Phase 2 设计校园 / 社群场景下的**共感式互动**（若当前仅为单用户原型，写清为阶段目标）。

### （三）研究方案与技术路线

- **必须补**：一页 **技术路线图**（五段即可）：数据与规范制备 → 情绪推断与模板 → 视觉/音频生成 → 系统集成与评测 → 试点与迭代。
- **每个阶段写清**：输入 / 输出、**关键难点**、**对应负责人**、**大致月份**。
- **避免**：仅罗列「选用某某大模型」而无「**如何用在本项目数据与任务上**」。

### （四）数据收集与处理

- **写明**：国画筛选标准（时期、类别、分辨率、版权或许可来源）；样本量分 **Pilot（小）** 与 **扩展（目标）**。
- **写明**：标注流程（培训、双人标注、一致性 / Kappa 或 α 的**计划阈值**）；不达标时的复标规则。
- **伦理**：心理相关数据需**脱敏、知情说明、校内伦理或指导老师把关**；不写「区块链」除非真实实施。

### （五）实验与评估（务实版）

- **建议主方案**：前后测 + **用户体验 / 情绪自评**（如简易量表或 VIS 类问卷）+ **可用性题目**；对照组可弱化为「常规放松音频 / 纯文本」等非医疗标签。
- **生理指标（HRV、皮电等）**：建议写为「**条件具备时作为扩展观测**」，不作为唯一结题硬杠。
- **禁止写死**：如「量表得分平均降低 30%」等若无预实验支撑，改为「**显著改善趋势需经统计检验**」或删除具体百分比。

### （六）团队分工

- **增加表格**：姓名｜核心能力｜**本项目任务**｜**对接里程碑**（如数据集 v0.1、系统 α 版、校内答辩）。
- 与成员简历一致：**贾睿祺**（总协调、前端与集成、EmoLLM 与流水线）；**邢郅睿**（视觉质量、特征与论文）；**王晨旭**（数据与实验设计）；**宁健**（AIGC 与模块开发）等，按真实分工微调。

### （七）预期成果与考核指标

建议 **「保底（国项易验收）+ 争取（冲优）」** 两栏：

| 类型 | 保底建议 | 争取项 |
|------|----------|--------|
| 学术 | 会议 / 学报论文 1 篇；研究报告 1 份 | SCI/EI 增补（与团队经历一致可写） |
| 技术 | **可演示系统** 1 套；**软著** 1 项；**结构化数据集 / 标注规范** 1 套 | 开源片段或匿名样例 |
| 社会 | **1 份** 合作意向或校内心理相关联络纪要 | 多单位意向书、小型工作坊 |

**中期（约 6 个月）**：数据集与标注流程跑通、核心流水线稳定、系统主要功能可演示、1 次小规模反馈。  
**末期（约 12 个月）**：软著与论文推进、试点方案与总结、指标达成说明（**以自评 + 可用性为主**）。

### （八）经费预算

- 按学校下发的**额度**填列；科目示例：**数据与标注劳务、云服务 / API、印刷与量表、差旅与专家咨询、论文 / 软著、耗材**。
- 每一笔与**任务**一句话对应，避免「其他」占比过大。

### （十九）风险与应对

| 风险 | 应对要点 |
|------|----------|
| 生成质量不稳 | 模板库与负面 prompt 迭代；固定随机种子与评测集 |
| 版权与合规 | 优先公版 / 授权图；协议留痕 |
| 对接与试点难 | 导师牵头校内单位；先小范围志愿体验 |
| 隐私 | 匿名 ID、最小采集、权限与存储规范 |

### （十）格式与附件

- 删除**重复粘贴**的成员介绍与导师简介；表格列合并、章节层级统一。
- 附件：**获奖证明、导师证明、合作意向、标注规范初稿、技术路线图、`flow_01`～`flow_03` 架构图**（与文书一致）。
- **参考文献**：扩充至 **10～20 篇**，近 3 年占比提高；**正文举例与文献条目一致**（避免 Ellie 与 SimSensei 文献错配）。

## 六、总结一句

申请书要从「**概念全、口气大**」升级为「**创新点可数、路线可画、分工可查、成果可验、表述与仓库一致**」；**医学级疗效与超大样本**改为**合规、可完成的验证表述**，国评通过概率更稳。
